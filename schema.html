Database Schema — Airtable Base "TC Ops"

One Airtable base is the single source of truth. Every worker reads and writes here; workers never pass data directly to each other — status fields ARE the handoffs. Auth: Airtable personal access token (no expiry, no 2FA friction), scoped to this base only.

Build Order

  1. Create the base + Deals / Contacts / Counties / Utilities — manual data entry works from day one; humans can run the whole process on this base before any bot exists.
  2. Documents table + checklist templates.
  3. Tasks + Approval Queue + Audit Log.
  4. Templates with the brand kit.
  5. Then wire workers one at a time, starting with Intake / Parser — each worker goes live only after its section of this blueprint is approved.
